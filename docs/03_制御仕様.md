# 99L Mission Board 制御仕様

## 1. 制御目的

制御の目的は、エンジン燃焼終了後から頂点付近まで機体のロール角を一定に保つこととする。実装上は、エンジン燃焼終了後であることを十分保証できる離床+8秒以降の最初のControl開始時に、その時点の連続・unwrappedな機体ロール角を`control_roll_reference_unwrapped_rad`としてcaptureし、以後これを保持する。離床時刻の0 radは姿勢推定の座標原点であり、Controlでランチャー0へ戻す目標ではない。

Control時のLQR第1状態は`roll_deviation_unwrapped_rad = roll_estimate_liftoff_relative_unwrapped_rad - control_roll_reference_unwrapped_rad`とする。Control開始後の累積回転を全量戻す目標とし、360度周期の最短路へ変換しない。燃焼中に生じた累積roll角をランチャー0へ巻き戻さない。表示用のtarget-current符号は`corrective_roll_error_unwrapped_rad = control_roll_reference_unwrapped_rad - roll_estimate_liftoff_relative_unwrapped_rad`とし、LQR入力と同じ名前で扱わない。

reference=0 degからcurrent=+380 degになった場合、LQRの偏差は+380 deg、角度feedback torqueの符号はnegative、表示用corrective errorは-380 degである。-20 degとして扱わない。reference=+720 deg、current=+1100 degの場合も偏差は+380 degとする。

Control pathでは`wrapToPi`、`atan2(sin(d), cos(d))`、`mod(..., 2*pi)`、`[-pi,+pi]`へのnormalizationを使用しない。Quaternion由来のwrapped rollは表示またはsimulation truth比較に残してよいが、MissionLQRControl入力に使用しない。

## 2. 単位・符号規約

制御内部はSI単位とする。

- `φ`, `θ`: rad
- `φdot`, `θdot`: rad/s
- 要求出力軸torque: N·m
- pressure: Pa
- voltage: V
- current: A

`+θdot`は`+θ`が増加する向き、正の要求出力軸torqueは`+θ`を増加させる向きとする。

TB67H450FNG IN1/IN2と実機`+θ`の対応は実機低duty試験で確定し、コード上の静的設定`MotorPolarity`として`In1Positive`または`In2Positive`のどちらかを選択する。runtimeで`MotorPolarity`を変更するcommandや`Unconfigured`状態は設けない。bring-up時の方向確認はTorqueMapperを介さない試験用direct-duty操作で行い、確定値には`TODO(HW_TEST)`を残す。

## 3. PreflightCalibrationと姿勢推定

CommandReceiveの`RunPreflightCalibration`で最新gyro bias、gravity vector、launcher tilt、SSC zero offsetを求める。gyro biasは姿勢積分へ使用する。

gravity vectorだけでは重力軸まわりのrollは決定できないため、gravityはroll zeroには使用しない。roll zeroは離床時刻を基準とする。

ICM初期化後のCommandReceiveからraw gyro rolling bufferを常時1秒以上保持し、sensor timestamp、raw gyro XYZ、validityを保存する。離床検知時に最新valid gyro biasを適用して`liftoff_time = detection_time - 1 s`からreplay積分し、その後もsensor timestampを用いて`roll_estimate_liftoff_relative_unwrapped_rad`のリアルタイム積分を連続する。Sensor/姿勢推定moduleはliftoff-relative unwrapped estimateを返し、Control targetを差し引かない。

### 3.1. Control roll reference

`control_roll_reference_unwrapped_rad`、`control_roll_reference_valid`、`control_roll_reference_capture_tick`、`control_roll_reference_estimator_timestamp`を姿勢推定stateとは分離してMission/Control coordinatorが所有する。

EngineBurnからControlへのrising edgeで、最新のvalid/fresh姿勢sampleを最初のControl演算より前に一度だけcaptureする。captureと最初の演算は同じlatest-complete sampleを使用するため、最初の`roll_deviation_unwrapped_rad`はexactly 0 radになる。`roll_rate_rad_s`は0へ置換せず、そのsampleの値を使用するため、非零rateならentry tickからrate項torqueが出る。

reference未capture、姿勢invalid、または姿勢staleならRoll Controllerを実行しない。Control中は再captureしない。reset、新flight epoch、`CancelSequence`、`LiftoffDetectionEmergencyStop`でinvalidにする。estimator sample timestampはcapture時刻以下でなければならない。

### 3.2. ICM42688欠落sample

単一sample欠落だけで即姿勢invalidにしない。

初期実装では連続欠落許容数を1 sampleとし、timestampから1 sample欠落と一意に判断できる場合は未来sampleを待たず、そのtickでは直前rateを1 ms積分する。次のvalid tickではそのrateを1 ms積分することで、2 ms全体では前後sampleの台形積分と等価になる構成を使用できる。

## 4. Controlへの移行条件

Control移行判定は離床時刻から8秒以降に行う。

Controlへ入るには以下をすべて満たす。

- `fin_control_disabled == false`
- 動翼0度保持valid
- 有効airspeed > 60 m/s
- 姿勢推定valid
- LPS25HB available/fresh
- SSCDRRN005PD2A5 available/fresh
- gyro bias valid
- SSC zero offset valid

+8秒時点でfin zero hold、姿勢、airspeed>60のいずれかが成立しない場合は、その飛行中`control_reentry_inhibited=true`とする。

LPSまたはSSCがControlに必要な時点でUnavailableの場合もControlへ入らず、その飛行中のControl再移行を禁止する。復旧後の再entryは行わない。

一回のtransport errorだけで即Unavailableにせず、最後の正常値がfreshness範囲内かつHealth上利用可能なら使用できる。freshnessや60 m/s gate debounceには`TODO(SIMULATION)`または`TODO(HW_TEST)`を残す。

## 5. Control中の停止

以下でControlを停止しEngineBurnへ戻り、その飛行中のControl再移行を禁止する。

- airspeed <= 60 m/sの停止debounce成立
- 姿勢推定invalid
- 動翼角/動翼駆動系invalid
- LPS25HB unavailable
- SSC unavailable
- `DisableFinControl`受理

`fin_control_disabled=false`かつZeroHoldに必要な状態がvalidならControl停止後はZeroHoldへ移る。それ以外はBrakeとする。

LPS/SSC driverの復旧自体は継続してよく、復旧後の値はtelemetry、logging、頂点検知へ利用できるがControl再entryには使用しない。

## 6. 制御処理の責務分離

以下を独立moduleとする。

1. Roll Controller: validな状態量から要求出力軸torqueを計算
2. ZeroHold Controller: fin angleを0へ保持する要求torqueを計算
3. Fin Velocity Estimator: AS5047D系列から`θdot`を推定
4. TorqueMapper / Motor Actuator: 要求出力軸torqueからmotor電流・電圧・PWMへ変換
5. Mission/Control coordinator: MissionState、Health、freshness、`fin_control_disabled`等からRollControl / ZeroHold / Brakeを選択

Controller内部でMissionStateやdevice接続状態を判定しない。

Control演算とPWM duty/direction更新周期は**1 kHz**とする。

## 7. Roll Controller

状態は`x = [roll_deviation_unwrapped_rad, fin_angle_rad, roll_rate_rad_s, fin_rate_rad_s]^T`とし、`u = -Kx`で要求出力軸torqueを出力するstate feedback controllerとする。曖昧な`wrapped_roll_angle`や符号が逆の表示用`error`をLQR入力名に使用しない。

firmwareでは飛行中にAREを解かず、60, 80, 100, 120, 140, 160, 180 m/sのairspeed設計点で事前計算したgain tableを保持し、設計点間を線形補間する。60 m/s以下ではControlしない。gain lookupはControl gateとは別責務とし、Control active時のlookup値が60 m/s未満なら60 m/s、180 m/s超なら180 m/sへclampしてendpoint tableを使用する。table外extrapolationとrange errorによる制御停止は禁止する。

gain lookupにはraw推定airspeed、実際にlookupしたairspeed、`gain_lookup_clamped_low`、`gain_lookup_clamped_high`を残す。Control inactive時はlookupを呼ばなくてよい。係数mismatchでrange外となってもraw値を失わず、gate判定値とlookup clampを同一flagで扱わない。

Control内では`CNα=2.59 rad^-1`を現在の基準値とし、Mach依存のonline補正やonline ARE再計算は初期実装では行わない。これらはSpicaで再評価する。

初期Q/R、gain tableは現Spica Phase 3候補を使用してよいが、飛行用確定値ではなく`TODO(SIMULATION)`とする。実測actuator/sensor modelを取り込んだPhase 9で再設計する。

## 8. ZeroHold Controller

初期実装はPD型`u = -Kp * θ - Kd * θdot`としてよい。

初期候補は以下とするが、すべて`TODO(SIMULATION)`である。

- `Kp = 2.32 N·m/rad`
- `Kd = 0.296 N·m·s/rad`
- ZeroHold output torque limit候補: 0.80 N·m
- HoldPosition / relative test torque limit候補: 0.30 N·m
- ZeroHold valid候補: `|θ| <= 1 deg`, `|θdot| <= 5 deg/s`を100 ms連続

## 9. 動翼角速度`θdot`

Spica Phase 5ではlinear regression、quadratic regression、alpha-beta filterを比較し、現評価基準では**3点quadratic regression、latest capture timeで微分**がactive motionのRMSE/peak/phase delayで優位なsimulation candidateとして選ばれている。この結果は1 kHz single-sample pipelineのhistorical candidateとして保持する。

実機multi-rate characterizationでは、acquisition rateを1/2/5/10 kHz、consumer rateを1 kHzとし、`acquisition_hz / consumer_hz`が整数であることを要求する。各blockは1/2/5/10 sampleの非重複blockとし、raw compensated angleをsampleごとにunwrapしてからblock statisticを求め、最後にtotal ratioへ変換して1 kHzでestimator/controlを更新する。capture timestampはvalid subsample timestampの算術平均、release timestampは最後のsubsample SPI完了時刻とする。

1/2/5/10 kHzのlast sample、`block_arithmetic_mean_n1/n2/n5/n10`、block median、必要な場合のみsliding mean、および係数をretuneしないdirect high-rate estimator updateを比較する。direct high-rate updateはnoise rejectionのrejection comparatorであり、production候補ではない。通常候補はnon-overlap block arithmetic meanとし、2 kHzと5 kHzをnoise、delay、steady-state reliability、dynamic error、implementation costのPareto比較で選ぶ。5 kHzを事前採用せず、新しい結果はprovisional candidateとしてflight estimatorを自動切替しない。

estimator方式はinterfaceで差し替え可能にするが、flight中にruntime切替は行わない。

2 kHzまたは5 kHz captureはtimer/high-priority producer、1 kHz controllerはdeterministic consumerとして分離するか、同等のdeadline保証を示す。1 kHz Control tickをN回のSPI blocking read完了周期へ従属させない。consumer tick時に新blockが無い場合はfuture sampleを待たず、last complete sampleとage/freshnessを使用し、deadline miss、repeated block、staleをlogする。

`EncoderPipelineState`は`Uninitialized / WarmingUp / Ready / Faulted`とする。`Ready`はcomplete block、strict monotonic timestamp、valid filtered angle、estimatorの必要history、freshnessのANDである。Quadratic N=3はfiltered sample 3点、alpha-betaはその初期化要件を満たすまで`WarmingUp`とする。`StartSequence`またはControl entry時に`Ready`でなければControl input unavailableとし、同期的にwarm-up完了を待たない。

AS5047D sample invalid、unwrap不能、大きなtimestamp gap等ではestimator stateをinvalid/reset可能にする。

## 10. 動翼角limit・backlash・支持剛性

飛行時hardware/mechanical limitは**±15 deg**である。`|θ| > 15 deg`は絶対に許容しない。

mechanical stopperへの接触自体は直ちに制御FAILとはしない。構造系審査書の実機・構造評価値として以下を使用する。

- 実測backlash全幅: **0.344 deg = 0.00600 rad**
- 回転方向支持剛性: **269.43 N·m/rad**
- stopper構造評価torque: **7.10328 N·m**
- stopper FM相当静的確認: **10.65 N·mを30 s保持**
- 通常制御時必要保持torqueの構造側上限: **2.66526 N·m**
- stopperなし駆動系構造評価torque: **1.21208 N·m**

Spicaのbacklash modelで対称dead-zoneを使用する場合は全幅0.344 degを根拠値とし、半幅の扱いをmodel定義内で明示する。直進位置残留角の安全評価では構造審査書どおり0.344 degを保守値として使用する。

飛行用software angle limitは`FinSoftwareLimits`相当の単一configから参照し、Controller、relative move、TorqueMapperへ値を散在させない。最終software limitはfin/stopper組付後の停止角、Brake応答、encoder誤差、backlash、latencyを実測して決定する。

## 11. MotorProfileと動翼駆動系

使用motor/gearの基本構成は以下とする。

- maxon 110158 A-max22 6W
- maxon 134162 GP22A
- GP ratio `729/25`
- bevel ratio `145/24`
- total ratio **176.175 : 1**

メーカー公称初期値は以下とする。

- nominal voltage: 9 V

- torque constant: 8.55 mN·m/A
- speed constant: 1120 rpm/V

予備motorへ交換可能であり、個体ごとに抵抗、摩擦、dead-zone、応答等が変化する可能性があるため、controllerへ直接埋め込まず`MotorProfile`から供給する。

## 12. TorqueMapperと制御authority候補

要求出力軸torqueからtotal ratioと駆動系効率を用いてmotor torqueを求め、torque constantからcurrent、motor speedとspeed constantからBEMF、terminal resistanceから必要motor voltageを計算し、実測motor bus voltageからPWM dutyを求める。

駆動系効率の初期候補として0.60を置いてよいが`TODO(HW_TEST)`とする。

用途別の要求torque上限を次の独立configとして保持し、曖昧な単一`torque_limit`を複数controllerへ流用しない。いずれもsystem identification前の候補値であり、flight用確定値ではない。

- `hold_position_limit_Nm`: HoldPosition / relative test **0.30 N·m**
- `zero_hold_requested_torque_limit_Nm`: ZeroHold **0.80 N·m**
- `roll_control_gentle_limit_Nm`: Roll Control Gentle **1.21208 N·m**
- `roll_control_high_authority_limit_Nm`: Roll Control High-authority comparator **3.0 N·m**

0.80 N·mをRoll Control Gentleとして使用してはならない。SpicaではRoll ControlをGentle / High-authority / Control OFFで比較し、ZeroHoldの0.80 N·mは`ZeroHoldAuthorityComparator`等の明示名で別用途の比較に限る。

Gentleで十分な制御性能を得られる場合はGentleを優先する。High-authorityでなければ要求性能を満たせずstopperへのdynamic contactが発生する場合は、simulationが要求する接触速度まで段階的な実機qualification testを行ってから採用可否を判断する。

TB67 hardware current settingは2.2 A、PWM carrierは30 kHz、duty/direction更新は1 kHzとする。

NaN/Inf、bus voltage invalid、変換不能、内部error等ではPWMへ変換せずBrakeとする。

## 13. Stopper contactのsimulation判定

Spicaではstopper接触を少なくとも以下の3値で分類する。

- `PASS`: `|θ| <= 15 deg`かつ構造・実機確認済み範囲内
- `FAIL`: `|θ| > 15 deg`またはstatic contact torqueが構造評価範囲を超える
- `NEEDS_HW_VALIDATION`: 未実機確認のdynamic impactが発生

stop contact時には最低限以下を記録する。

- contact count
- first contact time
- `theta_dot` at contact
- max static contact torque
- total contact duration
- max absolute fin angle

stopperの10.65 N·m試験は静的保持試験であり、高速衝突時の運動energy許容値を直接保証しない。stopper衝突試験はPhase 6開始条件にはしない。

### 13.1. 統合classification

stopperだけでrun全体を判定せず、少なくとも`stopper_classification`、`motor_speed_classification`、`gearbox_speed_classification`、`numeric_classification`、`control_performance_classification`、`overall_classification`を別fieldとして保存する。`overall_classification`は`FAIL > NEEDS_HW_VALIDATION > SAFE_DEGRADED > MISSION_PASS`のworst-ofとする。

- NaN / Inf / solver exception: `numeric_classification=FAIL`
- `|θ| > 15 deg`: `FAIL`
- motor speed > 9800 rpm: `motor_speed_classification=FAIL`
- static stopper contact torque > 7.10328 N·m: `stopper_classification=FAIL`
- 未qualificationのdynamic stopper contact: `stopper_classification=NEEDS_HW_VALIDATION`
- GP22A continuous input speed > 6000 rpm: exceed durationを記録し、少なくとも`MISSION_PASS`にしない
- hard limit違反はなくてもControl no-entry、false early stop、または未settle: `control_performance_classification=SAFE_DEGRADED`

Control entry transientとControl開始後の外乱は別scenarioとし、post-disturbance windowだけのPASSでentry transientまたはwhole-runのfailureを隠さない。

## 14. AirData

LPS25HBは25 Hz、SSCは400 Hz、I2Cは300 kHzとする。対気速度はLPS静圧、SSC差圧/温度、source nominal Pitot coefficient **K=0.92**を使用するサン・ブナン式でMission側にて計算する。historical schemaの曖昧な`pitot_coefficient=0.92`はsource nominalの意味で保持し、新runtime/simulation contractでは次を分離する。

- `pitot_coefficient_true`: 実際のpitot / pressure plantへ使用する値
- `pitot_coefficient_assumed`: Mission firmwareのairspeed変換に使用する値。primary assumptionは固定`0.92`

simulationでtruth airspeedから差圧を生成する際は`pitot_coefficient_true`、差圧からMission推定airspeedへ復元する際は`pitot_coefficient_assumed`を用いる。同じ係数を両方向へ流用してmismatchをcancelしてはならない。source nominalそのものを書き換えず、provisional robustness truth rangeを`0.60..1.20`、primary sweepを`[0.60, 0.70, 0.80, 0.92, 1.00, 1.10, 1.20]`とする。`K_true=1.00, K_assumed=0.92`をmandatory mismatch caseとし、matched consistencyは0.60 / 0.92 / 1.00 / 1.20で確認する。

固定した差圧に対してairspeedがKとともに単調増加する性質を用いて、diagnostic用`mission_airspeed_interval_from_pressure`相当は`K_min=0.60 / K_nominal=0.92 / K_max=1.20`からairspeed min/nominal/maxとvalidity/reasonを返す。このintervalはoffline robustness policy比較用であり、source-fixed Control gateを自動変更しない。

最低logはK true/assumed、true/nominal推定airspeed、absolute/relative error、interval min/max、raw/endpoint-clamped gain lookup airspeed、clamp flags、Control gate判定値とする。

SSC zero offsetはPreflightCalibration中に求め、LiftoffDetection中に自動rolling更新しない。

SSC差圧filterの初期候補として8 sample moving averageを置いてよいが`TODO(SIMULATION)`とする。

LPS25HB internal averagingはdriver default任せにせず明示設定し、初期候補pressure/temperatureとも8 samplesとする。Mission側5 sample meanと合わせたdelayをSpicaで評価する。

LPS/SSCがControl用としてUnavailableになった場合は、その飛行中のControl再entryを禁止する。

### 14.1. Moving-fin空力係数のuncertainty

controller gain tableと`controller.design_model.Clda_per_rad`はnominal sourceへ固定し、actual plantだけに`moving_fin_CN_a_scale_true`を適用する。primary provisional rangeは`[0.50, 0.75, 1.00, 1.25, 1.50]`とし、`TODO(SIMULATION/AERO_VALIDATION)`を付ける。

scale対象はbody roll momentとcommon shaft hinge/aero loadに使う**movable-fin componentだけ**とする。fixed fins、whole-vehicle `CNalpha_per_rad`、controller nominal gain model、source workbook/JSONをscaleしない。actual plantのequivalent Cldaはdiagnosticとして別計算する。body roll authorityとhinge loadへ同じscaleを整合適用し、0以下のscaleはrejectする。

このrangeはfin装着system identification前のrobustness precheck専用であり、最終airdata/aero range、Roll gain table、ZeroHold gain、fin software limitを確定しない。one-shot flightではonline coefficient identification、online adaptation、gain learning、case別retuneを行わず、事前検証した固定gain tableと固定`pitot_coefficient_assumed`を使用する。
