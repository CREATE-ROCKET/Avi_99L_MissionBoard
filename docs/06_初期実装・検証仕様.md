# 99L Mission Board 初期実装・検証仕様

## 1. 本文書の位置付け

本書は、Mission Board本実装へ着手する直前の初期実装値、実機検証順序、bring-up完了条件をまとめる。

00〜05は本書で決定した内容を反映し、00〜07を一体の仕様として扱う。本書はbring-upと検証手順、`TODO(SIMULATION)` / `TODO(HW_TEST)`の具体運用を補足する。

初期実装の第一目的は本番シーケンスを完成させることではなく、`CREATE-ROCKET/Avi_ESP_Libs`の`refactor` branchで今回使用するAPIが実基板上で正しく動作することを確認し、制御・推定・filter等の未確定係数を決めるための実測データを取得することである。

## 2. 現在の実機検証構成

- Mission Boardは実基板をPCへUSB接続して試験する。
- ESP32-S3は`/dev/ttyACM<N>`として認識されるものを使用し、番号をhardcodeしない。
- 差圧系以外は接続した状態で試験する。
- 差圧系未接続はbring-up failureとは扱わず、AirData実機試験のみskip可能とする。
- 動翼DC motorには現在動翼を取り付けていない。
- 現在の動翼駆動系には機械stopperがなく、360度以上連続回転可能である。
- bring-up段階では飛行時software limitを適用せず、test専用duty/speed/time limitで安全化する。
- 動翼motorのstep、PRBS、coast、Brake等のsystem identificationを実施してよい。ただし低duty・短時間から段階的に上げる。

## 3. Avi_ESP_Libsの利用方法

`CREATE-ROCKET/Avi_99L_MissionBoard`では`CREATE-ROCKET/Avi_ESP_Libs`を`lib/Avi_ESP_Libs`のGit submoduleとして使用する。

- 対象branch: `refactor`
- 実際の利用revisionはsubmodule commit SHAで固定
- remote `lib_deps`で毎build時に取得しない
- submoduleとPlatformIO/ESP-IDF toolchain取得済みならoffline build可能

Mission本実装より先に以下を実基板で個別検証する。

- `SPICREATE`
- `ICM42688`
- `AS5047D`
- `CANCREATE`
- `I2CCREATE`
- `LPS25HB`
- `SSCDRRN005PD2A5`
- `STSCREATE`
- `STS3215`
- `avi::Timeout`

library側の問題をMission Board側workaroundで隠さず、共通driver/APIの責務に属する不具合はsubmodule側を修正し、library build/testとMission実機試験を再実施する。

## 4. 初期bring-up順序

1. USB/書込み/build確認
2. reset/download/write/normal boot中のmotor安全確認
3. 起動直後GPIO安全状態確認
4. SPI transport単体確認
5. AS5047D normal/status/pipelined 1 kHz/連続回転確認
6. ICM42688 self-test/FIFO/timestamp/1 kHz連続取得確認
7. CAN 125 kbit/sの送受信・100 Hz load・bus-off/recovery確認
8. STSCREATE/STS3215の非駆動通信、status、torque disable/hold、小角度move確認
9. I2C/AirDataは差圧系接続時に確認。現在未接続ならskip
10. microSD SDMMC 4-bit確認
11. internal Flash専用partition read/write/erase/verify
12. ADC motor/logic電圧確認
13. TB67H450FNG低duty回転・正負方向・AS5047D追従確認
14. motor system identification log取得
15. preflight calibration用長時間静置log取得
16. 取得結果をSpica Phase 6へ入力できる形式に整理
17. 以上を反映してMissionのdriver/service層を実装

## 5. MotorProfileと実機characterization

動翼motorには予備個体があり、使用個体により抵抗、摩擦、dead-zone、駆動応答等が変わる可能性がある。motor依存値をcontrollerやTorqueMapperへ直接埋め込まない。

現在のfin/stopper未装着状態で最低限以下を取得する。

### 5.1. 静置

- ICM raw accel/gyro 1 kHzを5分以上
- ICM sensor timestamp/FIFO status
- AS5047D raw angle
- acquisition jitter
- logic/motor voltage
- queue drop/SD latency

### 5.2. motor step

正負方向について5%、10%、15%程度の短時間stepを段階的に実施する。最初は5%から行い、異常な高回転・発熱・異音があれば中止する。

### 5.3. PRBS

fixed seedのPRBSを100 Hz程度で与え、sensor/encoderは1 kHzでlogする。最初は±5%、問題なければ±10%、必要性を確認した場合のみ±15%へ進む。

### 5.4. coast / Brake

一定速度まで回した後にHi-Z coastとShort Brakeを別々に実施し、速度減衰、停止時間、停止角、振動を比較する。

### 5.5. 得るparameter

この実測から最低限以下を求める。

- motor polarity
- duty/Vbus→steady speed
- dead-zone
- command→motion delay
- step/PRBS dynamic response
- equivalent drivetrain inertia候補
- Coulomb/viscous friction候補
- coast/Brake response
- encoder jitter/noise
- motor駆動時ICM noise/vibration
- Vbus sag
- scheduler/SD logging jitter

個体ごとの結果をMotorProfile候補として保存し、予備motorでも同じ試験を再利用できる構造にする。

## 6. 構造系審査書から既に使える実測値

以下は新たにmotor-only試験で求める必要はなく、構造系審査書の実機評価値を初期Spica modelへ使用できる。

- backlash全幅: **0.344 deg = 0.00600 rad**
- 回転方向支持剛性: **269.43 N·m/rad**
- hardware angle limit: **±15 deg**
- stopper構造評価torque: **7.10328 N·m**
- stopper静的proof: **10.65 N·m / 30 s**
- 通常制御時必要保持torqueの構造側上限: **2.66526 N·m**
- stopperなし駆動系構造評価torque: **1.21208 N·m**

backlashを対称dead-zoneとしてmodel化する場合は全幅/半幅の定義を明示する。安全評価の直進位置残留角には0.344 degを保守値として使用する。

## 7. Stopper衝突試験の位置付け

stopperへmotorで意図的に衝突させる実機試験は、Phase 6開始条件にはしない。

構造系審査書の10.65 N·m / 30 s確認は静的保持試験であり、高速衝突時の運動energy許容値を直接保証しない。

SpicaでHigh-authority candidateがstopper dynamic contactを必要とする場合にのみ、simulationが要求する最大接触速度を基準として段階的なqualification testを計画する。

試験する場合は低速から開始し、各段階でbacklash、歯車異音/損傷、AS5047D基準、stopper変形、作動後のガタを再確認する。GP22Aを破損させる条件まで上げない。

## 8. PreflightCalibration

CommandReceiveで`RunPreflightCalibration`を何度でも実行可能にする。

1回のattemptでは利用可能なデバイスについて以下を同時に評価する。

- ICM42688 gyro bias
- gravity vector
- launcher tilt
- SSCDRRN005PD2A5差圧zero offset

最新attemptのみ使用し、失敗項目を古い成功値へrollbackしない。

bring-up用初期calibration時間は3秒としてよいが`TODO(HW_TEST)`を残す。

差圧zeroはLiftoffDetection中にrolling更新せずPreflightCalibration中に求めてfreezeする。

Calibration中はFin/Para駆動command、motor試験、`StartSequence`を`Busy`で拒否する。

## 9. ICM42688欠落sampleの初期方針

初期実装では連続欠落許容数を1 sampleとし`TODO(SIMULATION)`とする。

1 sample欠落tickで未来sampleを待たず直前rateを1 ms積分し、次valid tickでそのrateを1 ms積分することで2 ms全体を前後sample台形積分と等価にする。

許容数を超える欠落、timestamp gap不明、FIFO format fault、gyro invalid/saturation、timestamp不整合では姿勢をinvalidにする。

## 10. Fin Velocity Estimator

Spica Phase 5の現評価ではquadratic regression N=3がactive motionのRMSE/peak/phase delayでalpha-betaより優位なsimulation candidateとなっている。

したがってbring-up/初期production candidateとしてquadratic N=3を使用してよい。ただしPhase 5 noiseは実測値ではないため、今回取得する実機encoder/motor noiseをSpicaへ入力し、quadratic N=3とalpha-betaを再比較して最終決定する。

`TODO(SIMULATION)`を残す。

## 11. Fin software limit

bring-up時点のmotorは360度連続回転可能であり、動翼・stopperは未装着である。

飛行時software angle limitは`FinSoftwareLimits`等の単一configから参照する構造だけを用意し、最終値はfin/stopper組付後のBrake停止角、encoder error、backlash、latencyを測って決定する。

hardware limit **±15 deg**は絶対条件である。

## 12. AirData異常時のControl

LPS25HBまたはSSCDRRN005PD2A5がControlに必要な時点でUnavailableとなった場合、復旧後のControl再移行は行わない。

一回のtransport errorだけで即Unavailableにせず、最後の正常値がfreshness内でvalidなら利用できる。availability/freshness/debounceは`TODO(SIMULATION)` / `TODO(HW_TEST)`とする。

LPS25HB internal averagingはdriver default任せにせず、初期候補pressure/temperatureとも8 samplesとする。

## 13. Flash backup / memory freeze

internal Flash backupは初期50 Hz程度としてよいが`TODO(HW_TEST)`を残す。

flight backup用Flash領域はCommandReceive中に事前eraseし、飛行中はpre-erased領域へのappend writeのみとする。飛行中にeraseしない。

`CommandReceive -> LiftoffDetection`をmemory freeze境界とし、LiftoffDetection移行前までに全Task/stack、queue、driver、SD mount、flight log open、ring/buffer、timer、ADC calibration、Flash buffer等を確保する。

LiftoffDetection以降はapplication codeからdynamic heap allocation、container growth、新規Task/queue生成、filesystem mount、未準備file open、大規模local stack確保を行わない。

## 14. Recovery

Recoveryは**Deep Sleepのみ対応**する。Light Sleep fallbackは持たない。

初期候補として10秒periodic wakeを使用し、Recovery専用boot pathでADC/CAN/Recovery statusを更新し、短時間commandを待って再sleepする。`TODO(HW_TEST)`。

標準remote log dumpはInternal Flash backup。Mission microSD full-rate logはoffset/length指定の部分dumpとする。

可能ならrequested dataをCANで通信基板microSDへ先にspoolし、Mission Boardは再Deep Sleepして通信基板だけでLoRa送信を継続する。

## 15. Bring-up完了条件

Mission本実装へ進む前に、少なくとも以下を満たす。

- 今回使用する`Avi_ESP_Libs/refactor` APIが実機で個別に正常動作
- driver error pathとtimeoutがhangせず戻る
- actuator初期化時に意図しない動作がない
- AS5047D 1 kHz continuous/pipelined取得、回転方向、error handling確認
- ICM42688 1 kHz FIFO/timestamp/長時間静置/lost-full-fault確認
- CAN 125 kbit/s、100 Hz load、recovery確認
- STS3215 read/status/disableTorque/hold/small move確認
- I2C no-device時有限return
- SD/Flash/ADC基本I/O確認
- motor identification用の再現可能なlog取得
- gyro bias/noise等の静置log取得
- 実機logをSpica Phase 6へ入力できる形式に整理

この段階では飛行用最終Control係数やstopper dynamic impact limitの確定を完了条件としない。
