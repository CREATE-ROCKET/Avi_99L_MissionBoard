# 99L Mission Board 実装仕様

## 1. 適用対象

本仕様はMission Boardの実装対象基板として`temp_new.kicad_pcb`を使用する場合の具体的なハードウェア・firmware設定をまとめる。

KiCad上のValueと実際の実装品が異なる場合は実装済みBOMを優先する。

初期実装時は[[06_初期実装・検証仕様|初期実装・検証仕様]]のbring-upを先に実施し、`Avi_ESP_Libs/refactor`の今回使用APIを実機検証してからMission本実装へ進む。

## 2. MCU・開発環境

- MCU: `ESP32-S3-WROOM-1-N16R8`
- Framework: ESP-IDF
- Build system: PlatformIO
- 言語: C++17
- ESP32 Platform: `espressif32@7.0.1`を基準
- 共通library: `CREATE-ROCKET/Avi_ESP_Libs` `refactor`

### 2.1. Avi_ESP_Libs submodule

`Avi_ESP_Libs`は`lib/Avi_ESP_Libs`へGit submoduleとして配置する。

- source: `https://github.com/CREATE-ROCKET/Avi_ESP_Libs`
- tracking対象: `refactor`
- 実際の利用revision: submodule commit SHAで固定
- build時にremote `lib_deps`としてGitHubから取得しない
- submoduleとPlatformIO/ESP-IDF toolchain取得済みならoffline build可能とする

`refactor`は今回のMission Board実機で十分な検証がまだないため、少なくとも`SPICREATE`, `AS5047D`, `ICM42688`, `CANCREATE`, `I2CCREATE`, `LPS25HB`, `SSCDRRN005PD2A5`, `STSCREATE`, `STS3215`, `avi::Timeout`を本Mission実装前に個別検証する。

library責務のbugをMission Board側workaroundで隠さず、必要ならsubmodule側を修正しlibrary build/testとMission実機testの両方を再実行する。

### 2.2. PlatformIO boardとconsole

project-local board manifest`boards/avi_99l_missionboard.json`を用意し、N16R8に合わせて16 MB Flash、8 MB PSRAM、ESP32-S3の構成を明示する。

Primary debug consoleはUSB Serial/JTAGを基本とし、GPIO44等のアクチュエータ関連pinをconsole UARTへ使用しない。

高rate realtime bufferやDMA/task stackは内部RAMを基本とし、PSRAMへ置くものは明示的に管理する。

## 4. 起動安全化

`app_main()`の可能な限り早い段階で、他driver/task開始前に最低以下を確立する。

- GPIO38 LOW
- GPIO39 LOW
- GPIO40 LOW (`+5V_short` OFF)
- GPIO44 LOW (Para OFF)

TB67はStop/Hi-Zから開始する。

bring-up actuator testは自動実行禁止。motor testはRAM-onlyのarm stateを必要とし、reboot時は必ずdisarmとする。

eFuseによるPad JTAG無効化は既に実施済みである。bring-upではreset/download/write/normal boot中にmotorが意図せず動作しないことを実機確認して記録する。

## 5. センサ設定

### 5.1. ICM42688

- SPI 8 MHz
- accel ±16 g
- gyro ±2000 deg/s
- accel/gyro ODR 1000 Hz
- initial filter `odr_div4`
- INT GPIO15
- FIFO enabled
- watermark 1 record
- sensor timestampを姿勢積分へ使用

ICM初期化後のCommandReceiveからraw gyro rolling bufferを常時1秒以上保持する。

単一sample欠落を補間可能な初期構造を持たせ、連続欠落許容数1には`TODO(SIMULATION)`を残す。

### 5.2. AS5047D

- SPI 8 MHz
- `AngleSource::compensated`
- pipelined read
- characterization acquisition: 1000/2000/5000/10000 Hz、production比較候補: 2000/5000 Hz capture、1000 Hz estimator/control update
- raw compensated angleをsampleごとにunwrapした後で算術平均し、最後にtotal ratioへ変換
- block capture timestampはvalid subsample timestampの算術平均
- block release timestampは最後のsubsample完了時刻

飛行中はpipelined angle readを優先し、diagnostic目的でpipelineを定期停止しない。詳細diagnosticはCommandReceive/bring-upで確認する。AS5047D producerはCommandReceive中から開始可能とする。

2 kHzまたは5 kHz captureはtimer/high-priority producer、1 kHz Mission/Controlはdeterministic consumerとして分離する。N sample SPI blocking loopの完了時刻を次のControl tick開始時刻にしない。ring/bufferは固定容量とし、consumerはそのtickのlatest complete blockだけを取得する。新blockが無い場合はfuture sampleを待たず、last complete sampleとage/freshnessを使用し、deadline miss、repeated block、stale、coalescingを記録する。

Fin Velocity Estimatorは1 kHz single、2 kHz 2-point block mean、5 kHz 5-point block meanの各quadratic N=3/alpha-beta、10 kHz 10-point block meanのstatic sensitivity、ideal/empirical timingを比較する。alpha-beta .40/.35を最終値とせず、必要ならpipelineごとにgrid sweepする。direct 2/5/10 kHz estimator updateは係数をretuneしないnoise rejection comparatorに限る。5 kHzを事前採用せず、flight方式を自動切替しない。`TODO(SIMULATION)`を残す。

`EncoderPipelineState` は`Uninitialized / WarmingUp / Ready / Faulted`とする。`Ready`にはcomplete block、strict monotonic timestamp、filtered angle valid、estimatorの必要history、freshnessを必須とする。Quadratic N=3はfiltered sample 3点まで、alpha-betaはその初期化要件を満たすまで`WarmingUp`とする。`StartSequence`またはControl entry時に`Ready`でなければinput unavailableとし、future sampleをblocking待ちしない。

### 5.3. AirData

- LPS25HB 25 Hz
- SSCDRRN005PD2A5 400 Hz
- I2C 300 kHz
- LPS=static pressure
- SSC=differential pressure + temperature
- source nominal Pitot coefficient `K=0.92`
- 対気速度は審査書のサン・ブナン式でMission側計算

production firmwareはsource nominalを`pitot_coefficient_assumed=0.92`として使用する。simulation側はpressure plantの`pitot_coefficient_true`とMission変換の`pitot_coefficient_assumed`を別configにし、同じ曖昧な`pitot_coefficient`を生成・復元の両方へ渡さない。robustness precheckのtruth range `0.60..1.20`とmoving-fin `CN_a` scale `0.50..1.50`はsource定数ではなく`TODO(SIMULATION/AERO_VALIDATION)`付きのprovisional rangeである。

diagnostic用airspeed intervalは固定差圧に対してairspeedがKとともに単調増加する性質を利用し、K=0.60 / 0.92 / 1.20のairspeed min/nominal/max、validity、reasonを返す。Missionのprimary gateをこのintervalへ自動変更せず、nominal gateとconservative interval候補をoffline比較する。

SSC zero offsetはCommandReceiveのPreflightCalibrationで求めてfreezeし、LiftoffDetection中に自動rolling更新しない。

SSC filter初期候補は8 sample moving average、LPS internal averaging初期候補はpressure/temperatureとも8 samplesとし、いずれもSpicaでdelay/noiseを再評価する。

Control中またはControl移行時にLPS/SSCがUnavailableとなった場合、そのflightではControl再entryしない。

## 6. PreflightCalibration

`RunPreflightCalibration`をCommandReceiveで何度でも実行可能とする。

各attemptで利用可能な範囲についてgyro bias、gravity vector、launcher tilt、SSC zero offsetを求める。最新attemptだけを使用し、失敗項目を古い成功値へrollbackしない。

初期calibration時間は3秒としてよいが`TODO(HW_TEST)`を残す。stationary判定thresholdも`TODO(HW_TEST)`。

Calibration中はFin/Para駆動command、motor試験、`StartSequence`を`Busy`で拒否する。

### 6.1. Roll estimateとControl reference

姿勢推定moduleは離床時刻を0 radとする連続な`roll_estimate_liftoff_relative_unwrapped_rad`とsample timestamp/validity/freshnessをpublishし、Control targetを差し引かない。Mission/Control coordinatorは別stateとして`control_roll_reference_unwrapped_rad`、`control_roll_reference_valid`、`control_roll_reference_capture_tick`、`control_roll_reference_estimator_timestamp`を所有する。

EngineBurn→Controlのrising edgeでは、最新のcompleteかつvalid/freshな姿勢sampleを取得し、referenceをcaptureしてから、その同一sampleで最初のRoll Controller演算を行う。reference capture前にLQRを呼ばず、Control中に再captureしない。reset、新flight epoch、`CancelSequence`、`LiftoffDetectionEmergencyStop`ではreferenceをinvalidにする。

LQR第1状態は`roll_deviation_unwrapped_rad = roll_estimate_liftoff_relative_unwrapped_rad - control_roll_reference_unwrapped_rad`とし、Control pathでshortest-path wrapを行わない。表示用逆符号は`corrective_roll_error_unwrapped_rad`として別fieldにする。

## 8. 動翼駆動

### 8.1. TB67H450FNG

実装品は`TB67H450FNG,EL`。

- PWM carrier **30 kHz**
- Control/PWM update **1 kHz**
- IN1=LOW, IN2=LOW: Stop / Hi-Z
- IN1=HIGH, IN2=HIGH: Short Brake
- VREF=3.3 V
- hardware current setting **2.2 A**

motor polarityは実機低duty試験で確定し、コード上の静的設定`MotorPolarity`として`In1Positive`または`In2Positive`のどちらかを指定する。runtimeで変更しない。

### 8.2. MotorProfile

motorは予備個体と交換可能なため、motor依存値を`MotorProfile`として差し替え可能にする。

基本構成:

- maxon 110158 A-max22 6 W
- maxon 134162 GP22A
- GP ratio `729/25`
- bevel ratio `145/24`
- total ratio **176.175:1**

メーカー公称初期値は9 V、R=3.48 Ohm、Kt=8.55 mN·m/A、Kv=1120 rpm/Vとする。

個体実測値、friction、dead-zone、dynamic response、efficiencyは`TODO(HW_TEST)`。

### 8.3. backlash・支持剛性・stopper

構造系審査書のFM相当実測/評価値を使用する。

- backlash全幅: **0.344 deg = 0.00600 rad**
- 回転方向支持剛性: **269.43 N·m/rad**
- hardware angle limit: **±15 deg**
- stopper構造評価: **7.10328 N·m**
- stopper静的proof: **10.65 N·m / 30 s**
- 通常制御時必要保持torqueの構造側上限: **2.66526 N·m**
- stopperなし駆動系評価: **1.21208 N·m**

飛行用software limitはfin/stopper組付後にBrake停止角・angle error・latency等を実測して決定する。

### 8.4. TorqueMapper候補

用途ごとのconfigを分離し、同じgeneric `torque_limit`を使い回さない。

- `hold_position_limit_Nm`: HoldPosition / relative test **0.30 N·m**
- `zero_hold_requested_torque_limit_Nm`: ZeroHold **0.80 N·m**
- `roll_control_gentle_limit_Nm`: Roll Control Gentle **1.21208 N·m**
- `roll_control_high_authority_limit_Nm`: Roll Control High-authority comparator **3.0 N·m**

0.80 N·mはRoll Gentleではない。Gentle/High-authorityの2系統にControl OFFを加えてSpicaで比較可能にし、ZeroHold authority comparatorは別scenario/configにする。

Gentleで十分な性能ならGentleを優先する。High-authorityでstopper dynamic contactを必要とする場合は、simulation結果から実機qualification条件を決める。

## 9. パラシュート

- STSCREATE UART 1 Mbpsを基本
- RX41 / TX42
- direction_enable NC
- STS ID 1

絶対角のcanonical representationは1回転4096 countの`AbsoluteParachuteAngle`とし、0..4095だけをvalidとする。CommandReceive用設定はoptionalなOpen/Close、飛行用は非optionalな`FlightParachuteConfiguration`とする。

`ParachuteTask`はSTSCREATE、STS3215、UART、active設定、flight snapshotの唯一ownerとする。通常Startはfresh現在角をHoldし、Open/Closeとexact half-turn条件を検証してsnapshotをfreezeする。Close位置へ移動しない。Descent/Openとretryはsnapshot Openだけを使い、actual move直前のfresh現在角から共通の最短円周変位を求める。

`InternalFlashTask`はNVSの唯一ownerとする。startupで一度だけ`nvs_flash_init()`を行い、自動`nvs_flash_erase()`は行わない。namespace `para_cfg`、独立key `open_v1` / `close_v1`へ16 byte v1 blobを保存し、set、commit、readback、decode、count一致の確認後だけ`ParachuteTask`のactive設定を更新する。

Open/retryよりさらに上位のSafety処理として離床+25秒絶対電源遮断を独立実行可能にする。

STS speed/torque、Open確認tolerance、Shock閾値は`TODO(HW_TEST)`。

## 11. 実装BOM差分

実装BOMをKiCad Valueより優先する。少なくともQ2/Q3=`TCKE812NA,RF`、U15=`SP3485EN-L/TR`、U3=`TB67H450FNG,EL`を実装値とする。

## 12. Flash partitionとpersistence

初期partition構成:

- NVS: 64 KiB
- PHY init: 4 KiB
- factory app: 4 MiB
- internal flight backup log: 2 MiB
- 残り: 将来用/未使用

NVS checkpointはflight critical pathを待たせないbest-effort補助系とする。flight中はRAM/RTC stateを先に更新し、NVS writeはbounded queueへnon-blocking requestする。

internal Flash backup領域はCommandReceive中に必要範囲を事前eraseし、LiftoffDetection以降はappend writeのみとする。飛行中にeraseしない。

`ExportFlashLogToSdAndErase`ではSDへの完全保存をverifyした場合だけflightlog partitionをeraseする。

## 13. microSD logging

Mission microSDはSDMMC 4-bitを使用し、primary full-rate flight logを保存する。

高rate primary logはbinary fixed-formatを基本とし、C++ struct paddingやnative endianに依存せず明示serializeする。1 kHz data pathで大量の`printf`を使用しない。姿勢logには`roll_estimate_liftoff_relative_unwrapped_rad`、`control_roll_reference_unwrapped_rad`、reference valid/capture tick/estimator timestamp、`roll_deviation_unwrapped_rad`、必要な場合の表示用wrapped orientationを別fieldとして残す。旧historical schemaの`wrapped_roll_deviation_rad`は改名・再解釈しない。

AirData/Control logにはsource nominal/assumed K、diagnostic K interval、raw estimated airspeed、gain lookup airspeed、low/high clamp flag、Control gate判定値を含める。simulation artifactではさらにK true、true airspeed、estimate error、moving-fin CN scale、actual equivalent Cldaを保存する。flight firmwareが未知のK trueを推定済みとして記録してはならない。

encoder timing logにはraw capture requested timestamp、SPI transaction start/completion timestamp、block completion/release timestamp、1 kHz consumer timestamp、consumer deadline miss、repeated block count、coalesced notification count、raw capture missed tick count、timestamp offset saturation count、pipeline ready timestampを含める。startup warm-upとReady後のsteady-state qualityを別fieldで追跡する。

logging queue overflowはdrop counterを残す。SD異常でMissionを停止しない。

通信基板microSDはCAN量子化済みtelemetryをLoRa downsample前に保存する別の冗長系である。

## 14. CommandReceive→LiftoffDetection memory freeze

LiftoffDetectionへ遷移する前に、flight中に必要な大規模resource確保とlazy initializationを完了する。

少なくとも全Task/stack、queue/semaphore/event、driver begin、SD mount、flight log file open、I/O buffer、gyro ring、control/estimator/logging buffer、ADC calibration、timer、Flash buffer、flight用Flash事前eraseを済ませる。

LiftoffDetection以降はapplication codeから`new/delete/malloc/calloc/realloc/free`、container capacity growth、Task/queue等の新規生成、filesystem mount、未準備file open、大規模local stack確保を行わない。

StartSequence直前にheap integrity、free/minimum/largest internal heapを記録し、integration testではflight全pathでheap tracingとtask stack high-water markを確認する。

## 15. Task / concurrency

安全優先度は以下とする。

**deployment条件監視・絶対電源遮断 > Para Open/UART > 1 kHz Mission/Control > AirData > CAN > persistence/logging**

基本Task:

- `SafetyTask`: deployment条件、+17/+25、cutoff latch。blocking I/O禁止
- `ParachuteTask`: STS UART/Open/retry。STS UART唯一owner
- `EncoderCaptureTask`: timer駆動high-priority AS5047D producer。2/5 kHz比較後のprovisional rate、SPI2/ringの唯一writer
- `MissionRealtimeTask`: 1 kHz FSM/ICM/encoder block consumer/fin control、Control reference capture。MissionStateとControl referenceの唯一writer
- `AirDataTask`: SSC/LPS/I2C唯一owner
- `CanTask`: CAN RX/TX/recovery
- `CommandWorkerTask`: command dispatch、Calibration、長時間command管理。device直接ownerにしない
- `HousekeepingTask`: ADC/LED/低rate Health/時刻
- `InternalFlashTask`: NVS + internal Flash backup
- `SdLogTask`: SDMMC唯一owner

`SafetyTask`はMissionStateを書き換えずrequest/latchを立て、MissionRealtimeTaskが次の1 ms tickでDescentへ遷移する。

GPIO40/GPIO44等のpower enableは単一arbiterを通し、cutoff latch後は再投入不能にする。

具体的priority number/stack sizeは実測調整可能だが相対優先度とownershipを維持する。

## 16. Recovery

Recovery sleepは**Deep Sleepのみ対応**する。Light Sleep fallbackは実装しない。

RecoveryEnter後にSD/Flash flush、安全output、RTC Recovery marker保存を行ってDeep Sleepへ入る。

Deep Sleep wakeでは通常flight boot pathへ戻らずRecovery専用boot pathへ入り、必要最小限のCAN/ADC/storage transferのみ初期化する。

初期候補として10 s periodic wakeを使用し、battery ADC/CAN statusを更新して短時間command待機後に再sleepする。`TODO(HW_TEST)`。

標準remote dumpはInternal Flash backup、Mission microSDはoffset/length指定の部分dumpとする。可能なら通信基板microSDへ先にCAN spoolし、Missionは再Deep Sleepする。

## 17. Spica v3.1変更方針

現Spica Phase 1〜5を土台として使用する。Phase 6以降は[[07_実装前最終確認・シミュレーション仕様|07]]に従う。

要点:

1. 現Vault sourceへrebase
2. V2/V4実機characterization log import
3. 1/2/5/10 kHz filter pipelineとquadratic N=3 / alpha-betaを実機noise・timingで再比較
4. measured backlash 0.344 deg、support stiffness 269.43 N·m/radをactuator modelへ導入
5. Gentle/High-authority torque candidateを比較
6. stopper contactをstatic strengthとdynamic impactへ分離
7. system-ID非依存のPitot true/assumed分離、moving-fin plant uncertainty、gain lookup endpoint clamp、用途別authorityを先に実装
8. Phase 8を開始せず、Phase 9 final retuneとは別の`robustness_prework`としてfixed-table coefficient sweepを実行
9. fin装着/finなしmotor gearの新system identification後に、ZeroHold、encoder pipeline、Roll gain、software fin limitを最終化
