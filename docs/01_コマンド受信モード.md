# 99L Mission Board コマンド受信モード仕様

## 1. 前提

コマンド受信モードは電源投入直後の準備状態である。

この時点では以下が未接続でも許容する。

- 動翼モータ系統
- パラシュートサーボ
- 気圧計・差圧計系統

デバイスが未接続または正常動作していないこと自体を理由にSequence Startを禁止しない。ただし、飛行に必要な設定値が未設定の場合はSequence Startを拒否する。

CommandReceiveでは各種driverのbring-up、校正、設定、Flash backup export等を何度でも実行可能にする。初期実装段階の検証方法は[[06_初期実装・検証仕様|初期実装・検証仕様]]に従う。

## 2. 起動直後のアクチュエータ安全化

driverやtaskの初期化より先に、アクチュエータへ意図しない出力が出ないGPIO状態を確立する。

最低限、起動直後は以下とする。

- TB67H450FNG IN1/IN2をLOWとしてStop / Hi-Z
- `+5V_short` EnableをLOW
- パラシュート系EnableをLOW

`+5V`常時ON系統とGPIO40で制御する`+5V_short`を混同しない。

その後に必要な電源・通信を段階的に有効化する。

通常のCommandReceive動作では、動翼とパラシュートを現在位置で固定することを試みる。

動翼はエンコーダから現在角度を取得できた場合はその位置で保持し、取得不能の場合はbest effortでBrakeとする。パラシュートサーボは現在角度を取得できた場合はその位置をHoldし、取得不能の場合はbest effortの安全化を行う。

bring-up用motor試験はboot時に自動実行せず、RAM-onlyの明示的なarm状態を経た場合だけ許可する。再起動時は必ずdisarmから開始する。

## 3. デバイス再接続

CommandReceive中は未接続または正常動作していないデバイスに対して1秒ごとに接続・動作確認を再試行する。

正常に動作するようになった場合はHealthおよび地上局telemetryを更新する。

actuatorの再接続時に初期Holdへ勝手に戻さず、現在要求されている`FinMode` / `ParaMode`を維持する。特に`ActuatorEmergencyStop`後はrequested modeがFreeであるため、deviceが再接続されても自動HoldしてEmergency Stopの効果を暗黙解除しない。専用解除commandは不要で、その後の通常commandがrequested modeを変更する。

`Avi_ESP_Libs/refactor`は本Mission Boardで十分に実機検証されていないため、Mission本実装より先に今回使用するAPIを個別に実機検証する。library側の責務に属する不具合をMission Board側のad-hoc workaroundで隠さない。

## 4. CANおよびLoRa通信

CommandReceiveではCANにより通信基板と通信できるか確認し、通信基板からLoRaを介した地上局との通信状態を取得する。

CANまたはLoRa通信が確立していない場合は通信回復を試みる。CANがbus-off等になった場合はCAN recoveryを行う。

すでに受理して実行を開始した通常コマンドは、CANまたはLoRa通信が途切れても中断しない。

Mission Board向け通常コマンドはgeneric command request/result形式を使用する。具体的なwire formatは[[04_通信仕様|通信仕様]]に従う。

## 5. コマンド実行モデル

動翼系、パラシュート系、校正・storage系は互いに可能な範囲で並列実行可能とする。

同一系統で通常コマンド実行中に、その系統の別の通常コマンドを受信した場合はqueueに入れず`Busy`として拒否する。

通常のStop/Free系commandは別の通常commandを暗黙に割り込ませない。Emergencyのみ通常commandへ割込み可能とする。

Sequence Start時に競合する動翼、パラシュート、Calibration、Flash export/erase、bring-up motor試験等が実行中の場合は`Busy`として拒否する。

`RunPreflightCalibration`は静置状態を前提とするため、実行中は動翼・パラシュートを動かす通常command、bring-up用motor試験、および`StartSequence`を`Busy`として拒否する。CAN telemetry、sensor取得、通常loggingは継続してよい。

逆に動翼・パラシュート駆動commandまたはbring-up motor試験中も`RunPreflightCalibration`を`Busy`として拒否する。

長時間commandは`Accepted`と最終`Completed/Failed`を分離して通知する。

## 6. CommandReceiveで使用する主なgeneric command

少なくとも以下を用意する。

- `StartSequence`
- `FinFree`
- `SetFinZero`
- `StartFinZeroHold`
- `FinMoveRelative`
- `ParaFree`
- `ParaHold`
- `ParaMoveRelative`
- `SetParaOpen`
- `SetParaClose`
- `ParaOpen`
- `ParaClose`
- `RunPreflightCalibration`
- `ExportFlashLogToSdAndErase`
- `SelectMotorProfile`

`CancelSequence`および`DisableFinControl`もgeneric commandであるが、受理するMissionStateは飛行シーケンス側で定義する。

## 7. ActuatorEmergencyStop

`ActuatorEmergencyStop`は[[02_飛行シーケンス|飛行シーケンス]]の`LiftoffDetectionEmergencyStop`とは別commandであり、通常generic commandとは別の専用Emergency messageとする。

**CommandReceiveでのみ受理**する。

受理した場合は実行中の動翼・パラシュート操作へ割り込み、動翼とパラシュートをどちらも手で動かせるFree状態へ移行する。

この操作は専用Emergency latchを追加するものではない。解除commandは設けず、requested Fin/Para modeをFreeとして維持し、その後の通常commandにより変更する。

割り込まれた通常commandは`InterruptedByEmergency`相当の失敗として結果を返す。

## 8. 動翼試験操作

CommandReceiveでは以下を操作できる。

- Free / Stop状態へ移行し、手で動かせるようにする
- 現在位置を論理上の動翼角0度として設定する
- 動翼角0度保持を開始する
- 相対角度を指定して移動する

動翼角0度設定と0度保持開始は別操作とする。

相対角度指定は0.1度単位とし、エンコーダが正常に利用できる場合のみ実行する。保持状態から相対移動した場合は移動完了後に新しい位置の保持状態へ戻る。

相対移動のtorque、stall判定、ZeroHold係数等は初期値を置いて実装してよいが、simulationまたは実機で最終決定する値には`TODO(SIMULATION)` / `TODO(HW_TEST)`を残す。

`SetFinZero`が正常に完了した場合のみ`FinZeroConfigured=true`とする。Mission Board reset時は必ず未設定へ戻す。

現在のbring-up状態では動翼本体・stopperがなくmotorは360度以上連続回転可能である。bring-up motor testへ飛行用±15度software limitを適用せず、test専用duty/speed/time limitを使用する。飛行用software limitは動翼・stopper取付後に決定する。

## 9. MotorProfile

動翼motorには予備個体があるため、motor依存値をcontrollerやTorqueMapperへ直接埋め込まない。

`MotorProfile`相当の設定として、少なくともprofile ID、motor電気定数、駆動系効率、current/torque limit、ZeroHold tuning、必要に応じたControl tuning/tableを差し替え可能にする。

`SelectMotorProfile`はCommandReceiveのみで受理し、選択profileをNVSへ永続化する。profile変更時は`FinZeroConfigured`を無効化する。

MotorPolarityはruntime profile選択とは別にコード上の静的設定とし、実機低duty試験で確定する。

## 10. PreflightCalibration

`RunPreflightCalibration`を何度でも実行可能にする。

1回のattemptでは、利用可能なデバイスについて以下を同時に評価する。

- ICM42688 gyro bias
- 重力加速度vector
- 重力vectorから得られるlauncher tilt
- SSCDRRN005PD2A5差圧zero offset

校正中は機体がランチャー挿入後に静置されていることを前提とする。初期calibration時間は3秒としてよいが`TODO(HW_TEST)`を残す。

各校正量は最新attemptの結果だけを使用する。最新attemptで失敗した項目を以前の成功値へ自動rollbackしない。

重力vectorはlauncher tiltや取付異常の確認へ使用するが、重力軸まわりのroll zeroを決めるためには使用しない。roll zeroはliftoff基準とする。

差圧zeroはLiftoffDetection中に自動rolling更新せず、PreflightCalibrationで求めてfreezeする。差圧系が未接続の場合はSSC zeroのみinvalidとして、gyro bias/gravity calibrationを独立して成功させてよい。

PreflightCalibration自体はSequence Start必須条件にしない。ただしgyro biasやSSC zeroがvalidでない場合、それらを必要とするControl入力はvalidにならない。

## 11. パラシュート試験操作

CommandReceiveではFree、現在位置Hold、相対角移動、Open/Close位置設定、Open/Close動作を実行できる。

角度指定はsigned値とし、正を時計回り、負を反時計回りとする。最短方向を自動選択しない。1回の移動量は180度以上を使用しない。

Open位置、Close位置、Open/Close方向はNVSへ永続化し、保存成功時のみ設定済みとする。

## 12. Flash backup log export

`ExportFlashLogToSdAndErase`はCommandReceiveのみで受理する長時間generic commandとする。

内部Flash backup log scan/CRC確認 → microSD書出し → flush/sync → SD再確認 → 完全保存確認後のみFlash erase、の順とする。失敗時はFlashを消去しない。

## 13. LiftoffDetectionへの遷移

地上局から少なくとも`FinZeroConfigured`、`ParachuteOpenConfigured`、`ParachuteCloseConfigured`、MotorProfile、PreflightCalibration各valid状態を確認できるようにする。

Sequence Start必須設定は以下3項目とする。

- `FinZeroConfigured`
- `ParachuteOpenConfigured`
- `ParachuteCloseConfigured`

いずれか未設定なら拒否する。

さらにCalibration、Flash export/erase、bring-up motor試験、競合actuator command等の処理中は`Busy`として拒否する。

Sequence Start受理前に[[05_実装仕様|実装仕様]]のmemory freeze/preallocation条件を満たす。

Sequence Startを受理した時点で`fin_control_disabled=false`から新しいflight attemptを開始する。動翼角0度保持を開始し、CommandReceive中にすでに0度保持中なら継続する。パラシュートは遷移時点の現在位置でHoldする。
